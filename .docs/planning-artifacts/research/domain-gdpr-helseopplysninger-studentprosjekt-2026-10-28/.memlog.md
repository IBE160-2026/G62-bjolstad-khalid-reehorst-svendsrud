- (source) Applicability dimension, round 1: 11 sources (gdpr-info.eu Art 2/5/9/17, Recital 18, WP29 2015 letter via 3 law-firm summaries, EDPB Guidelines 03/2020 and 05/2020 via EDPB summary + secondary commentary, CJEU Lindqvist/Ryneš via secondary case-law summaries).
- (claim) ref=1 status=verified class=regulatory pub=2026-10 — GDPR's personal/household exemption (Art 2(2)(c), Recital 18) is narrow and personal to an individual; it does NOT extend to a team providing software to others. No carve-out exists for small/student/non-commercial/unpublished projects in the regulation text or EDPB guidance found.
- (claim) ref=2 status=unverified class=regulatory pub=2015 — diet/weight/exercise data is NOT automatically Art.9 special-category health data; it becomes so only when it reveals actual health status, but regulators (WP29 2015, EDPB 03/2020) lean toward a broad reading especially for longitudinal/aggregated data. Primary WP29/EDPB documents not fetched verbatim this session, relied on secondary summaries.
- (claim) ref=3 status=verified class=regulatory pub=2026-10 — if Art.9 applies, the simplest legal basis is explicit, specific, opt-in consent (Art 9(2)(a)); EDPB Guidelines 05/2020 require an express affirmative statement, not a default/opt-out, with a provable record and easy withdrawal.
- (claim) ref=4 status=verified class=regulatory pub=2026-10 — baseline obligations regardless of special-category status: data minimization (Art 5(1)(c)), storage limitation (Art 5(1)(e)), and a working right-to-erasure path (Art 17) — all confirmed directly against GDPR primary text (gdpr-info.eu mirror).
- (source) Pattern dimension, round 1: 10 sources (ICO consent guidance, EDPB Guidelines 05/2020 via secondary summaries, Diabetesforeningen privacy policy, Open Trackers/MyTracker/Lettest OSS privacy policies, Danish DPA erasure guide via JD Supra, vendor/practitioner blogs).
- (source) Datatilsynet/Sikt dimension, round 1: 13 sources (sikt.no personverntjenester-forskning direct fetch, datatilsynet.no personopplysninger direct fetch, helsedirektoratet.no Normen syntetiske-data, EDPB SME guide, 5 Norwegian university student-project pages, Danish Datatilsynet samtykke guidance, EU household-exemption secondary sources).
- (claim) ref=5 status=verified class=regulatory pub=2026-10 — Sikt's own site states its personverntjenester/meldeplikt is scoped to 'forsking' (research); students are covered only 'i forsking,' and each institution decides which project types are reported to Sikt. A graded course/class coding assignment is NOT automatically covered — this is institution-specific and not resolvable generically. Confirmed via direct fetch of sikt.no/tjenester/personverntjenester-forskning (primary source, direct quote).
- (claim) ref=6 status=unverified class=regulatory pub=2026-10 — no Datatilsynet.no guidance specifically for small/hobby/student projects was found (unlike Denmark's Datatilsynet, which has one); negative finding, may reflect search limits rather than confirmed absence.
- (claim) ref=7 status=unverified class=regulatory pub=2026-10 — purely fictional/synthetic test data is not personal data under GDPR per Helsedirektoratet's Normen guidance (single Norwegian source, not double-sourced from Datatilsynet/Sikt directly); data must be genuinely decoupled from real people to qualify.
- (claim) ref=8 status=unverified class=regulatory pub=2026-10 — ICO's 4-element consent test (freely given, specific, informed, unambiguous affirmative act) and EDPB Guidelines 05/2020 give the practical minimum for a consent screen; no Norway-specific (Datatilsynet) consent template was found, only UK/EU secondary sources.
- (claim) ref=9 status=unverified class=regulatory pub=2026-10 — real small/OSS fitness-tracker privacy policies (Open Trackers, MyTracker, Lettest) handle account deletion via manual request (support email or GitHub issue), not automated self-service pipelines; a student project with a soft-delete button + manual/scripted hard-delete shortly after would be at least as rigorous as these published real-world examples.
