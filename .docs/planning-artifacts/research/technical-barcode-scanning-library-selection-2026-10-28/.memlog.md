- (source) Round 1, 4 candidates: html5-qrcode (GitHub repo/README/API, issue #915), @zxing/library (GitHub repo/README, issue #286, Snyk, Ecosyste.ms), zxing-wasm (GitHub API live, jsDelivr README, Dynamsoft/STRICH vendor pages), native BarcodeDetector (caniuse.com, WebKit Bugzilla, Chrome for Developers docs, Apple Developer Forums).
- (claim) ref=1 status=verified class=performance pub=2024-04 — html5-qrcode: multiple independent users report EAN-13 recognition success under 10% on iPhone 13/15 (GitHub issue #915, open since 2024-04-18, 4 different users), contradicting the README's 'full support' claim for iOS Safari.
- (claim) ref=2 status=verified class=version/compatibility pub=2023-04 — html5-qrcode effectively unmaintained since April 2023 (last substantive commit/release), maintainer states maintenance-mode/no fixes, 448 open vs 334 closed issues; confirmed via GitHub API releases+commits+issue search (2 primary endpoints).
- (claim) ref=3 status=unverified class=version/compatibility pub=undated — @zxing/library: self-described 'maintenance mode only' but received 2 releases (0.22.0, 0.23.0) in April 2026 after a 20-month gap; partially confirmed (primary README + Snyk version history), net assessment is semi-active, not abandoned.
- (claim) ref=4 status=unverified class=version/compatibility pub=undated — @zxing/library: no recent (2025-2026) first-hand iOS Safari or Android Chrome real-device test found for EAN-13 specifically; gap, not a claim.
- (claim) ref=5 status=verified class=compatibility pub=2026-10 — zxing-wasm is decode-only, ships no camera/getUserMedia API; team must wire camera capture themselves or adopt a wrapper (barcode-detector, vue-qrcode-reader, etc.); confirmed directly against the official README.
- (claim) ref=6 status=verified class=version/compatibility pub=2026-10 — zxing-wasm is the most actively maintained of the 4 candidates: latest release 2026-10-19, repo pushed same day as this research, confirmed via live GitHub API (primary).
- (claim) ref=7 status=unverified class=performance pub=undated — zxing-wasm 'WASM decodes faster than pure JS' claim could not be corroborated by 2 independent non-vendor sources this session; only vendor benchmarks found, comparing to a different commercial engine, not to pure-JS ZXing. Flagged unverified.
- (claim) ref=8 status=verified class=version/compatibility pub=2026-10 — native BarcodeDetector is disabled by default in every shipped iOS Safari version 17.0 through 27.2 (caniuse.com), and even manually enabling it has an open unresolved regression (WebKit bug 281848); corroborated by WebKit Bugzilla bug 198174/255803. 2 independent sources — the single most load-bearing claim in this run.
- (claim) ref=9 status=verified class=compatibility pub=undated — native BarcodeDetector on Android depends on Google Play Services being present/current; constructor presence does not guarantee detect() succeeds (Chrome's own docs, primary source).
- (claim) ref=10 status=unverified class=version/compatibility pub=undated — the 'barcode-detector' npm polyfill for BarcodeDetector is itself built on zxing-wasm, so using it to patch the iOS gap re-introduces the same WASM cost the native API was meant to avoid; medium confidence, npmjs.com fetch blocked (403).
- (question) Quagga2 (@ericblade/quagga2) surfaced independently as a candidate wildcard by TWO separate research assistants (html5-qrcode's and @zxing/library's) — purpose-built for 1D/EAN-13, appears more actively maintained than html5-qrcode. Per the approved selection-shape plan ('screen for one wildcard, confirm no credible free option is missing'), this warrants a dedicated screening pass before finalizing the verdict.
- (source) Round 2 (wildcard screen), Quagga2: 5 sources (GitHub README/API/releases, npm registry API, Lightrun QuaggaJS issue mirror).
- (claim) ref=11 status=verified class=version/compatibility pub=2026-10 — Quagga2 is actively maintained: release 2026-10-21, commit pushed 2026-10-28 (today), ~monthly release cadence over the past year; confirmed via npm registry API + GitHub REST API (2 primary sources). Genuinely more active than html5-qrcode, not just assumed.
- (claim) ref=12 status=unverified class=performance pub=undated — Quagga2's iOS Safari EAN-13 reliability on a real device is unresolved; only an indirect, low-confidence signal exists (an old original-QuaggaJS issue, not quagga2 itself). This is the single open item that would need resolving before ranking Quagga2 against the other 3 candidates.
