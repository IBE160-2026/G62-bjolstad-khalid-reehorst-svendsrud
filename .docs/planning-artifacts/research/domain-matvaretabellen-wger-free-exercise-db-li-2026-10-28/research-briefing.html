Executive summary

All three datasets can be used, but not uniformly, and not for everything.

  • Matvaretabellen — safe to use for seeding food/nutrient data. Free, no key/registration, reuse (including commercial use) permitted with attribution, via XLSX/ODS download or a public JSON API [1][2][3]. The exact license label is disputed — Mattilsynet's own page says CC BY 4.0 [1], the national open-data catalog says NLOD 2.0 [4] disputed — but both are permissive, attribution-requiring, commercial-use-allowed licenses, so this does not block the decision.
  • wger — safe to use the exercise/ingredient data via its public API (no key needed), but not uniformly licensed: server code is AGPL-3.0 (irrelevant if only the API is consumed) while the data is separately Creative-Commons-licensed per entry — live data mixes CC-BY-SA 3.0, CC-BY 4.0, CC-BY-SA 4.0, CC0, and ODbL [10][11][12] verified. Store license + author per imported row — don't assume one blanket license.
  • free-exercise-db — JSON exercise text is public domain (Unlicense), no attribution needed [5][6] verified. Its bundled images are a live, unresolved risk — maintainer admits not knowing their source, a contributor thread traces likely sourcing to a non-open site, unresolved as of the latest commit [7][8] unverified / risky. Do not use the images from this dataset.

Biggest caveat: none of the three gives free, zero-bookkeeping exercise images. wger's images carry real but trackable per-image attribution; free-exercise-db's images carry real, currently unresolved legal risk. The group's existing plan to use YouTube embeds for exercise demonstration video sidesteps this cleanly.

Licensing — Matvaretabellen

Mattilsynet publishes Matvaretabellen as an openly licensed dataset. Its own terms page states the data is available under CC BY 4.0, usable freely for any purpose within the license (implying commercial use), and requires the citation "Matvaretabellen 2026. Mattilsynet. www.matvaretabellen.no" [1]. It can be downloaded as XLSX or ODS with no cost, login, or registration [2], and is also exposed through a public JSON/EDN API (foods, food groups, nutrients, LanguaL codes, sources), again with no key or registration, updated annually each autumn [3].

One discrepancy surfaced: the national open-data catalog (data.norge.no, Digdir) lists the same dataset under "Norwegian Licence for Open Government Data (NLOD) 2.0" rather than CC BY 4.0, across two catalog entries [4]. No source reconciles the two labels. In practice this doesn't change the decision — both licenses are permissive, attribution-requiring, commercial-use-allowed — but the exact label is disputed rather than settled; Mattilsynet's own primary-source page [1] should outweigh the third-party catalog metadata [4].

Confidence: verified on "free, attribution-required, no key needed." disputed on the precise license name.

Licensing — wger

wger's application code is AGPL-3.0-or-later, confirmed by its README and GitHub's license-detection metadata [10]. Its exercise/ingredient data is licensed separately — the README says "see individual entries," and the docs describe the initial data as CC-BY-SA 3.0 [10][11]. The live API shows this is only a partial description: /api/v2/license/ lists five licenses actually in use — CC-BY-SA 3.0, CC-BY 4.0, CC-BY-SA 4.0, CC0 1.0, and ODbL — and a sampled exercise (id 9, "Kettlebell Swing") is tagged CC-BY-SA 4.0 with a named author, not the "3.0" the docs imply [12]. Rule: read the license from each entry's own field when importing — never assume one project-wide license.

Exercise images carry their own per-image license/attribution fields (license, license_author, license_author_url, license_derivative_source_url); some originate from Wikipedia with a per-folder sources file [13]. The public JSON API (wger.de/api/v2/) needs no key or auth for anonymous GETs; no documented rate limit was found, though that's absence of evidence, not a confirmed absence of a limit [12] unverified.

CC BY-SA 3.0, named for the initial dataset, permits commercial use and adaptation but requires attribution and ShareAlike (adaptations must carry the same or a compatible license) [14].

One interpretive point, flagged by the research itself as an inference, not a sourced finding: consuming wger's data only through its API — not running/modifying its AGPL server — likely does not bring a separate client app's own code under AGPL, since AGPL's copyleft terms attach to the covered program itself, not unrelated API clients. wger itself does not state this anywhere. unverified — get a second opinion if load-bearing

Confidence: verified on the code/data split and per-entry variability. low on the AGPL-client inference and rate-limit policy.

Licensing — free-exercise-db

free-exercise-db (github.com/yuhonas/free-exercise-db) is licensed under The Unlicense — a public-domain dedication — confirmed independently by GitHub's license-detection metadata and the literal LICENSE.md text [5][6]. No attribution requirement, no copyleft; permits commercial or non-commercial reuse "by any means." The JSON exercise fields (names, equipment, muscle groups, categories, instructions) can legally be reused in a closed-source student app with no attribution needed [5] verified.

The bundled exercise images are a different story. In one GitHub issue, the maintainer stated he does not know where the images came from or whether they're royalty-free: "usage would be at your own risk" [7]. In a separate, longer-running issue (open since 2024-08-26, still open at the time of this research), a contributor identified likely sourcing from ExRx.net — a non-open-licensed site — and called for removal; another comment argued distribution would be "plain illegal... even via GitHub"; the maintainer acknowledged the problem and proposed placeholder images, but had not acted as of the most recent commit [8] unresolved risk. The repo is otherwise actively maintained (commit within the last ~2 months) and distributed only via the GitHub repo itself — no npm package [9].

Confidence: verified on the Unlicense status of the JSON data (two independent confirmations). High-confidence absence of clearance on the images — a documented, ongoing dispute, not a theoretical risk.

Cross-dimension insight

Each dataset split its license at a finer grain than "one license for the whole thing" — by label, by code-vs-data, or by text-vs-image (see the sections above). The implication is architectural: any table that caches or seeds data from an external source needs its own license/attribution field per row, not a single blanket credit line in the README — this applies equally to OFF-cached food products already flagged in the pre-PRD prep document, and to any wger-sourced exercises or images. Feed this to the architecture phase, not only the PRD's data-sourcing section.

Recommendations

  1. Use Matvaretabellen for the food/nutrient seed data (XLSX/ODS or the JSON API), with the Mattilsynet citation stored in the data-sources documentation. high confidence
  2. Use wger's public API to seed the exercise list, storing each entry's license and license_author fields rather than one project-wide line. high confidence
  3. Use free-exercise-db's JSON text fields only — not its bundled images. Source images from wger or the group's own material instead. high confidence
  4. Add an attribution/license metadata column to any table seeded or cached from an external source, per the cross-dimension insight above. high confidence
  5. Get a second opinion before treating the wger/AGPL inference (above) as settled, if it becomes load-bearing for the architecture or submission. low confidence

Open questions

  • Matvaretabellen's exact license name (CC BY 4.0 vs NLOD 2.0) is unresolved. Next step: email matvaretabellen@mattilsynet.no, or check the GitHub source-code repo's license file linked from the API docs. disputed
  • wger's rate-limit policy (if any) wasn't found documented; only tested with a single anonymous request. Next step: ask in a wger GitHub issue, or test with a short burst before relying on uninterrupted bulk seeding.
  • Whether wger offers an official bulk data dump/fixture wasn't confirmed either way. Next step: check the repo for a committed fixture, or ask in an issue.
  • wger's Terms of Service page returned only an anti-bot challenge during this research. Next step: retry later or request terms through another channel.
  • The AGPL/client-app inference for wger hasn't been independently verified against AGPL's own FAQ language. Next step: read the AGPL FAQ directly, or ask course staff if this matters for grading/submission.
  • How many of free-exercise-db's images are actually affected by the ExRx.net issue, and whether any takedown notice exists, wasn't established. Doesn't change the recommendation (avoid the images regardless) — noted for completeness.
